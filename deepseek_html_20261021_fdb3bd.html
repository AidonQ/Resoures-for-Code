C4-PlantUML Diagrams

把 C4 模型的分层表达，落成可版本控制、可 diff 的 PlantUML 文本

概览 何时使用 核心模式 速查表 执行步骤 常见错误 如何使用

1概览

C4-PlantUML 把 PlantUML 的文本绘图能力和 C4 模型的分层表达结合起来：用宏定义元素（Person、System、Container…），用关系宏连接元素，用布局宏控制方向。

它的价值不在“画得好看”，而在 架构描述和代码一样可版本控制、可 diff、可复用。

这个 Skill 的目标 让你在 30 秒内选对 include 文件，5 分钟内产出一张结构正确的 C4 图，而不是从 400 多行 README 里慢慢翻。

2何时使用

  • 需要一张 系统上下文图，说清“谁在用这个系统、它依赖哪些外部系统”
  • 需要一张 容器图，说清“这个系统由哪几个可部署单元组成、它们之间怎么通信”
  • 需要一张 组件图，深入某个容器，展示内部的逻辑模块
  • 需要表达 动态调用顺序 或 部署节点分布
  • 需要在 Markdown、文档、代码仓库里 直接嵌入架构图源码
什么时候别用 需要像素级自由排版、复杂装饰、非 C4 风格的图，直接用原生 PlantUML 或 draw.io；需要交互式下钻，看 LikeC4 或 GitDiagram。

3核心模式

BEFORE · 凭感觉写

打开空白 .puml 文件，不知道 include 哪个文件，元素类型凭感觉写，关系线四处乱飞。

AFTER · 五步走

按“图类型 → include 文件 → 元素宏 → 关系宏 → 布局宏”五步走。每类图只 include 一个主文件，元素和关系都用 C4 语义宏，布局用全局宏控制方向，不手工调坐标。

4速查表

图类型 → include 文件对照

图类型include 文件核心新增宏
System Context / Landscape C4_Context.puml Person、System、System_Ext、Boundary
Container C4_Container.puml 在 Context 基础上增加 Container、ContainerDb、ContainerQueue
Component C4_Component.puml 在 Container 基础上增加 Component、ComponentDb、ComponentQueue
Dynamic C4_Dynamic.puml 用 Index() / $index 给关系编号，表达调用顺序
Deployment C4_Deployment.puml 在 Container 基础上增加 Deployment_Node / Node
Sequence (C4 styled) C4_Sequence.puml 复用元素宏，但边界用 Boundary_End() 而不是 {}
硬性规则 C4_Container.puml 已经包含 Context 宏，C4_Component.puml 已经包含 Container 宏。不要同时 include 多个层级文件，否则重复定义会报错。

常用元素宏（Context + Container 层）

Person(alias, "Label", "?Descr", ?sprite, ?tags, ?link)
Person_Ext(alias, "Label", "?Descr")
System(alias, "Label", "?Descr")
System_Ext(alias, "Label", "?Descr")
SystemDb(alias, "Label", "?Descr")
SystemQueue(alias, "Label", "?Descr")

Container(alias, "Label", "?Techn", "?Descr", ?sprite, ?tags)
ContainerDb(alias, "Label", "?Techn", "?Descr")
ContainerQueue(alias, "Label", "?Techn", "?Descr")

System_Boundary(alias, "Label") { ... }
Enterprise_Boundary(alias, "Label") { ... }
Boundary(alias, "Label", ?type) { ... }

可选参数用 ?arg 标记；可以直接用 $arg=... 单独设置某个可选参数，不必填满前面的位置参数。

关系宏

宏方向用途
Rel(from, to, "label", ?techn)自动最常用，方向由布局引擎决定
Rel_R / Rel_L / Rel_U / Rel_D右 / 左 / 上 / 下强制某个方向
BiRel(from, to, "label")双向双向通信
Rel_Back反向表达“被调用”关系

Rel 的第 4 个参数是技术/协议标注（如 "HTTPS"、"JSON/HTTP"），不是描述。

布局宏

LAYOUT_TOP_DOWN()      ' 默认，从上到下
LAYOUT_LEFT_RIGHT()    ' 从左到右
LAYOUT_LANDSCAPE()     ' 横向
不需要显式调用 LAYOUT_TOP_DOWN() 它是默认行为。只有需要改变方向时才调用另外两个。PlantUML v2.12.0 之后 LAYOUT_LANDSCAPE() 与 Lay_*() 的组合行为有变化，旧行为可通过 !NO_LAY_ROTATE=1 恢复。

5执行步骤

1
选择 include 方式

三种方式按场景选：

方式 A · 标准库（推荐，零网络依赖）
!include <C4/C4_Container>

PlantUML 内置了最近发布的 C4 文件，不需要额外下载，也不需要联网。

方式 B · 远程最新版（需要联网）
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml
方式 C · 本地文件（离线 + 固定版本）
!include C4_Container.puml

下载仓库根目录的 C4_*.puml 文件，配合 PlantUML 命令行参数 -DRELATIVE_INCLUDE="." 使用。

2
先写元素，再写关系

不要一边写元素一边画关系线。先把同一层级的所有元素定义完，再集中写关系。这样布局引擎有完整的图结构，避免局部优化导致整体别扭。

Container 图最小可运行骨架
@startuml
!include <C4/C4_Container>

Person(admin, "Administrator")
System_Boundary(c1, "Sample System") {
  Container(web_app, "Web Application", "C#, ASP.NET Core", "Allows users to compare timelines")
}
System(twitter, "Twitter")

Rel(admin, web_app, "Uses", "HTTPS")
Rel(web_app, twitter, "Gets tweets from", "HTTPS")

@enduml

这个骨架来自官方 Getting Started 示例，可以直接作为最小可运行模板。

3
用标签和样式做轻量语义分组

当需要区分版本、环境、备份链路等维度时，用 AddElementTag / AddRelTag + $tags，而不是手工逐个改颜色：

AddElementTag("v1.0", $borderColor="#d73027")
AddElementTag("backup", $fontColor="orange")
AddRelTag("backup", $textColor="orange", $lineStyle=DashedLine())

Container(spa, "SPA", "angular", $tags="v1.0")
Container(archive, "Archive", "Audit", $tags="backup")
Rel_L(api, archive, "Writes", $tags="backup")

SHOW_LEGEND() 会自动生成图例，解释每个标签的含义。

4
控制方向，而不是硬调坐标

优先用 Rel_R / Rel_D 等方向关系宏，其次用 Lay_U / Lay_D / Lay_L / Lay_R 对无关系的元素做排列。Lay_Distance(from, to, ?distance) 用于微调间距，但应作为最后手段。

硬性检查点 如果一张图里出现大量手工坐标、空白行、隐形节点来“挤位置”，说明布局宏用错了方向，回到步骤 2 检查关系是否都用了方向宏。
5
按图类型补齐专用宏
  • Dynamic 图：用 Rel(..., $index=Index()) 或 SetIndex() 给调用编号，$index 会渲染成序号。
  • Deployment 图：用 Deployment_Node / Node 包裹容器，表达物理/虚拟部署节点。
  • Sequence 图：边界不要用 {}，用 Boundary_End() 结束；只支持扩展后的 Rel 宏，支持 $rel 指定 PlantUML 箭头类型。

6常见错误

❌ 同时 include 多个层级文件 C4_Container.puml 已经包含 Context 宏，再 include C4_Context.puml 会导致重复定义。只 include 最深的那一层。
❌ 把描述写在技术参数位置 Container(api, "API", "Handles business logic") 会把描述渲染成“技术”一栏。技术参数应写 "Java"、"Spring Boot"，描述用第 4 个参数。
❌ 用 Rel 代替方向宏后手工调整 方向不对时优先换 Rel_R / Rel_L，而不是加空白行或隐形节点。
❌ 在 Sequence 图中用 {} 画边界 C4 styled Sequence 图要求用 Boundary_End()，这是与所有其他图类型的明确例外。
❌ 依赖 NO_LAY_ROTATE=1 做新图 它只是兼容旧行为的开关，新图不应依赖这个模式。

7产生的价值

一张用 C4-PlantUML 写成的 Container 图，源码通常可以控制在 20–40 行，却能同时表达：系统边界、外部依赖、容器职责、技术栈、通信协议。

它可以直接提交进 Git 仓库，与代码一起 review；修改一个 Container() 调用，diff 只影响那一行，而不是一整张图片的二进制变更。

适用场景 对于需要反复讨论“这个服务该不该独立部署”“这个依赖是不是外部系统”的场景，改一行、渲染一次的成本，远低于打开绘图工具重画。

8这个 Skill 怎么用

把文件夹放到 ~/.claude/skills/ 或 ~/.agents/skills/。触发条件写在 description 里：当对话中出现“画 C4 图”“系统上下文”“容器图”“组件图”“PlantUML 架构图”等需求时，Skill 会被命中。

蒸馏时删掉了什么、保留了什么

类别内容
删掉 完整的 435 行 README、所有 VSCode/IntelliJ 插件配置、全部高级 sample、sprites 图标库的逐一列举、版本历史。
保留 include 的三种方式、四类图的宏选择、关系宏的方向控制、布局宏、标签机制、五个最常见的错误。
保留的依据 这五类内容覆盖了“从零到一张可用的 C4 图”的完整最短路径，其余细节在需要时查原仓库即可。
